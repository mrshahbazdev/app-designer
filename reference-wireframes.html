Timer semantics

Model lifetime (delete after window from send, read or unread) and burn-after-read (visible only for a window after open) as separate inputs. Effective removal time is the earliest policy event. Educational patterns: teaz.me — third-party overview (not an endorsement).

Lifetime / expiration

Server + client enforce deletion after the chosen interval from send time, independent of read state (subject to product policy).

Burn after open

After the recipient opens the message, it remains visible only for the burn window; then it is removed on their side and yours when synced.

13. Implementation checklist

  • Parity: inbox toolbar (New, threadSearch, inbox ⋮), row ⋮, chat header ⋮ + Verify — match states in HubChatsExperience.tsx.
  • Unified search / open DM: one field for @handle, $ prefix, or pasted wallet — ship Paste affordances (Hub chats + login wallet) so users never re-type hex; wallet directory matching still when API exposes linked addresses (filter is handle-only today).
  • Auth parity with /hub/login: password session + wallet signature session; surface OAuth / magic link where mobile ships web view or native equivalents.
  • Account & device details: Sounds, Mute chat, Secure Mode, device approval — keep in sync with overflow menus; document mobile order (panel below thread).
  • Edge states: signed-out banner, empty thread list, search-no-results — match threadsListError / filteredThreads branches; don’t ship dead ends without CTAs.
  • A11y: real menus must use focus trap / Escape where applicable; wireframes are static — validate roving tabindex on thread rows and aria-expanded on ⋮ triggers in implementation.
  • Groups tab: keep product copy independent; wire creation flows when API exists (currently toast-only).
  • Wire lifetime dropdown to EP_ORDER / persistEphForThread; add burn key storage when schema exists.
  • Placeholder + aria-label sync (ephemeralComposerPlaceholder pattern).
  • Header i / conversation sheet → thread retention + clear (light mock); production uses header menus above.
  • Markdown: sanitize; no raw HTML from peers.
  • Dark lane: Tailwind dm.*; this HTML is visual parity reference only.
  • QA: keyboard, screen reader labels on timer groups, contrast on red composer bar; menu dismiss on outside click (data-hub-chat-menu).
